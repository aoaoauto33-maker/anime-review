# 学習したこと

## 1. Jotai

**問題**
Linkやrouter.pushでuserIdやroleを毎回渡す必要があり、URLが複雑だった。
また、URLを書き換えてroleを偽装できる問題があった。

**解決**
JotaiでuserIdとroleを管理し、URLから渡さないようにした。
→ Linkがスッキリした。

※Jotaiはセキュリティ対策ではなく、認証にはサーバー側のチェックが必要。


## 2. ルーティング・ファイル構成

**問題**
ファイルを分離しすぎると、どのファイルがどの機能に繋がっているか分かりにくくなった。
途中で構成を変更すると、Linkやimportにも影響して修正が大変だった。

**解決**
多少階層が深くなっても、機能やURLの関係が分かる構成にした。
→ こまめにGitへコミットして、問題が起きたときに戻せるようにする。


## 3. ReactとNext.js

**問題**
ReactとNext.jsの使い分けが曖昧だった。

**解決**
状態管理やユーザー操作が必要なページはClient Componentを使用し、
adminのみのページはNext.js側で完結させた。

※Server ComponentとClient Componentの使い分けは今後の課題。


## 4. actions.ts・Prisma

**問題**
ページにPrismaの処理まで書くと、UIとDB操作が混ざって分かりにくくなる。

**解決**
actions.tsにPrismaの処理をまとめ、ページから関数を呼び出す形にした。
→ UIとデータ操作を分離できた。


## 5. データベース設計

**問題**
ReviewにanimeIdとepisodeIdの両方を持たせると、同じ情報を重複して管理することになる。

**解決**
ReviewにはepisodeIdだけを持たせ、
Review → Episode → Anime
と辿ってアニメを取得するようにした。
→ データの重複・不整合を防げる。
